1.2 - O programa abre /root enquanto ainda tem privilégios (setuid root), obtendo o descritor FD=3
Depois baixa privilégios com setuid(getuid()), mas não fecha o descritor nem o marca como close-on-exec
Como os descritores de ficheiro são herdados através de execve por defeito, a shell (já sem privilégios) herda o FD aberto para /root, mantendo uma “capability” que permite acesso indireto a recursos em /root apesar de ter perdido o EUID 0

O programa imprimiu Directory FD is 3 e lançou uma shell
Na shell, confirmamos o leak listando os descritores em /proc/$$/fd, onde se observa que o descritor 3 aponta para /root (3 -> /root), confirmado por readlink /proc/$$/fd/3 que devolve /root

Assim, fica provado que o descritor aberto quando o programa tinha privilégios foi herdado após o execve(), mantendo uma “capability” privilegiada mesmo depois do setuid(getuid())



1.4 - Código já com a correção:
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <sys/types.h>
#include <sys/stat.h>
#include <fcntl.h>

int main() {
    int dfd;
    char *argv[2];

    dfd = open("/root", O_RDONLY | O_CLOEXEC);
    if (dfd == -1) {
        perror("open /root");
        exit(1);
    }

    printf("Directory FD is %d\n", dfd);

    if (mkdir("/root/backupssi", 0700) == -1) {
        perror("mkdir /root/backupssi");
    }

    /* Drop privileges */
    if (setuid(getuid()) == -1) {
        perror("setuid");
        exit(1);
    }

    close(dfd);

    argv[0] = "/bin/sh";
    argv[1] = NULL;
    execve(argv[0], argv, NULL);

    perror("execve");
    return 0;
}

A vulnerabilidade é capability leaking via descritor de ficheiro
O programa setuid root abre /etc/passwd com permissões de escrita/append e depois executa /bin/sh sem fechar o descritor nem usar FD_CLOEXEC
Como os FDs são herdados no execve, a shell do utilizador normal herda o FD (no caso, 3  /etc/passwd), ficando com capacidade de escrita num ficheiro crítico



2.3 -
O exploit consiste em abusar do descritor de ficheiro herdado pela shell (FD leakado com escrita para /etc/passwd) para acrescentar uma nova entrada no final do ficheiro
A sugestão do enunciado cria um utilizador com UID/GID 0, pelo que após a escrita passa a existir uma conta com privilégios de root


2.4 -
Se um atacante conseguir escrever em /etc/passwd através do FD leakado, consegue criar/alterar contas do sistema. 
Ao acrescentar uma entrada com UID=0 e GID=0, passa a existir um utilizador equivalente a root, permitindo obter privilégios totais. 
Isto compromete completamente a confidencialidade, integridade e disponibilidade do sistema.

#include <stdio.h>
#include <stdlib.h>
#include <fcntl.h>
#include <unistd.h> 

int main() {
    int fd = open("/etc/passwd", O_WRONLY | O_APPEND | O_CLOEXEC);
    if (fd < 0) {
        perror("open /etc/passwd");
        exit(1);
    }

    printf("Passwd FD leaked: %d\n", fd);

    if (setuid(getuid()) == -1) {
        perror("setuid");
        exit(1);
    }

    close(fd);

    execl("/bin/sh", "sh", NULL);

    perror("execl");
    return 0;
}
